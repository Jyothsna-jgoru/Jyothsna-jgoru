<summary><b>Enterprise Multi-Agent SDLC Automation Platform</b> &nbsp;·&nbsp; <a href="https://jyothsna-jgoru.github.io/forgeguard-ai/">Live demo ↗</a></summary>

<br/>

**ForgeGuard AI** demonstrates a governed ticket-to-pull-request workflow: planning, repository analysis, proposed changes, validation, security review, documentation, and human approval. A deny-by-default MCP-style gateway enforces role-scoped tool access and records policy decisions.

Explore ready-made tickets, replay the agent stages, inspect a Spring Boot sample diff, and approve a simulated draft pull request. The public experience runs in the browser without sign-in or repository access; external integrations remain simulated.

[Source code ↗](https://github.com/Jyothsna-jgoru/forgeguard-ai)

`React` `TypeScript` `FastAPI` `LangGraph` `MCP` `Local RAG` `PostgreSQL` `Docker` `GitHub Actions`

</details>

<details>
<summary><b>AI SRE Copilot</b> &nbsp;—&nbsp; agentic incident diagnosis for microservices &nbsp;·&nbsp; <a href="https://jyothsna-jgoru.github.io/AI-SRE-Copilot/">Live demo ↗</a></summary>

<br/>

Diagnoses production incidents and writes a structured RCA grounded in **retrieved evidence** rather than model memory. A LangGraph planner-executor routes across an MCP tool gateway — log search, Kafka lookup, deployment checks, runbook retrieval — before anything is generated.

```
             across 50+ simulated incidents
validated    20 RPS at the API orchestration layer
```

`Python` `FastAPI` `LangGraph` `RAG` `Apache Kafka` `ChromaDB` `Ollama` `Streamlit` `Docker`

</details>

<details>
<summary><b>Real-Time Collaborative Editor</b> &nbsp;—&nbsp; op-based sequence CRDT</summary>

<br/>

Local-first editing where concurrent inserts and deletes from many clients **converge without locking**. Ops log persisted in PostgreSQL on RDS, S3 snapshots with compaction every 10k ops to bound replay cost, Redis backplane for horizontal scale-out.

```
validated    20 concurrent clients under offline reconnect
             and duplicate operations
```

`C#` `.NET` `Blazor WASM` `ASP.NET Core` `SignalR` `PostgreSQL` `Redis` `AWS`

</details>

<details>
<summary><b>Log-Structured Distributed Key-Value Store</b> &nbsp;—&nbsp; storage internals from scratch &nbsp;·&nbsp; <a href="https://lskv-systems-console.onrender.com/">Live demo ↗</a></summary>

<br/>

Built to understand durability, crash recovery and replication by implementing them. Append-only write-ahead log for writes, in-memory hash index for point reads, recovery by replaying the log from disk on startup, leader–follower replication validated through controlled failover.

```
throughput   10,000+ ops/sec on a single node
recovery     under 5 seconds from node failure
```

`Python` `Append-Only Log` `Crash Recovery` `Replication` `Distributed Systems`

</details>
